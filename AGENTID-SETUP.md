# AgentID rollout plan

## Current status

**Step 1 — Authentication foundation: complete**

The site now includes:

- Accessible `Sign in with AgentID` and `Sign out` controls.
- A non-secret Supabase browser configuration boundary.
- Session-state messaging and identity display.
- A dedicated `agentid-login.html` initiate-login entry point.
- Git ignore rules protecting local config and environment files.
- No AgentID client secret in browser code or committed files.

## Step 2 — Create the Supabase project

1. Create or select a Supabase project.
2. Open **Authentication → Providers → Custom Providers**.
3. Copy Supabase's exact callback URL.
4. Add the local site URL and production site URL under **Authentication → URL Configuration**.

Do not guess the callback URL.

## Step 3 — Register the AgentID application

From the repository root, run:

```bash
npx @agentmail/agentid-cli init \
  --name AshisDigitalHub \
  --redirect-uri "PASTE_THE_SUPABASE_CALLBACK_URL_HERE"
```

Use the default scopes unless the application needs owner information:

```text
openid email profile
```

Keep the generated client secret in a password manager or server-side secret store. Never add it to `public/`, `app.js`, or `index.html`.

## Step 4 — Configure the Supabase OIDC provider

Use these values in Supabase:

- Provider: `agentid`
- Discovery URL: `https://auth.agentid.com/.well-known/openid-configuration`
- Client ID: generated by AgentID
- Client secret: generated by AgentID
- Scopes: `openid email profile`
- Redirect URL: the exact Supabase callback URL

## Step 5 — Add the public browser configuration

Copy the example file:

```bash
cp public/auth-config.example.js public/auth-config.js
```

Replace only these placeholders:

- `supabaseUrl`
- `supabaseAnonKey`

The Supabase anon key is intended for browser use. The AgentID client secret is not.

## Step 6 — Configure AgentID's initiate login URL

After publishing the site, set the AgentID application's **Initiate login URL** to:

```text
https://YOUR_DOMAIN/agentid-login.html
```

For a GitHub Pages project site, the path may be:

```text
https://ashiskumardey136-code.github.io/html/agentid-login.html
```

Use the actual published URL shown by GitHub Pages.

## Step 7 — Test

Run locally:

```bash
npm start
```

Check:

1. The home page loads.
2. `Sign in with AgentID` opens the provider.
3. The browser returns to the site.
4. The verified identity appears.
5. Refresh preserves the session.
6. `Sign out` removes the session.
7. The initiate-login URL works with `?login_hint=...`.

Run diagnostics:

```bash
npx @agentmail/agentid-cli doctor
npx @agentmail/agentid-cli doctor --json
```

## Step 8 — Publish safely

Commit the source changes and `public/auth-config.example.js`. Keep `public/auth-config.js` local or inject it through the hosting workflow. Never commit `.env`, real client secrets, or private keys.
